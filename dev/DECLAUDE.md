## Working rules

1. More than one question/concern/option → terse numbered list, proceed in that order. Multiple lists become numbered sub-sections.
2. Keep this file current: any tooling/report-layout/theme/findings change updates CLAUDE.md in the same change. The top-level `CLAUDE.md` is a symlink to `dev/DECLAUDE.md` — one file under two names, so never compare the two or wonder which is authoritative. Keep updates in this file's compact style — facts, commands, numbers, gotchas needed to act; no narrative, history, or rationale for rejected approaches. Prefer editing an existing line over appending a new paragraph.
3. No source line numbers here (they silently rot) — refer to a function/identifier/grep-able snippet.
4. `dev/` is throwaway profiling tooling, not upstream material: one shared parser, one shared theme, no dead code, no duplicate systems. Anything a script writes must open from `file://` with nothing fetched at view time.
5. A request bundling several distinct changes → state a checklist up front, work in order, close with a short per-item report (done / changed from ask / not applicable) — no running narration.
6. **No fake data.** Every value on a page is a recorded measurement or plain arithmetic on recorded measurements (sum, difference, share, a formula named on the page like `CEst`). Never synthesize what a tool did not record — no apportioning, reconstruction, interpolation, or "plausible" stacks — and never present an estimate as a trace. If a tool cannot supply what a view needs (callgrind: per-call stacks, per-call time), the view is not built. A page says what was measured, by which tool, with which flags. A generator that invents structure is a bug to remove, not a feature to tune.
7. **Nothing URL-parsing-specific, ever.** Never suggest, build, document or report anything specific to URL parsing (`urlparser`, `lib/urlapi.c`) or to any one perf test, source file or function — `urlparser` was a first trial run, nothing more. Every test in `TESTS_C` is treated identically: no test names, file lists or per-test cases anywhere in `dev/`, every view is built for every test, and examples here read `<test>`/`<file>`.

## The Scripts

```sh
dev/perf2html.sh [--verbose] [--keep-raw] [--regenerate] [--report=DIR] [cmake_flags...]
dev/perf2html_diff.sh [--verbose] [--keep-raw] [--regenerate] [baseline-dir] [modified-dir] [report-dir]
dev/perf2html_batch.sh [--verbose] [--keep] [--keep-raw] [--regenerate] [cmake_flags...]
```

**Iterating on HTML: use `--regenerate`.** Any change to a generator (`dev/scripts/*.py`, `theme.css`, `theme.js`) is re-tested with `dev/perf2html_batch.sh --regenerate`, which rebuilds all three reports' pages from the raw data of their own last run — no build, no callgrind, no perf stat, no trace runs, seconds instead of ~2.5min. Measure again only when the *thing being measured* changed (a `lib/` edit, different cmake flags, a new test). `--regenerate` needs raw data to exist: the run that recorded it must have been given `--keep-raw`, since `dev/trace/` is deleted at startup otherwise.

## Build

```sh
cmake -S . -B build -G Ninja -DCURL_USE_LIBPSL=OFF
cmake --build build --parallel
cmake --build build --target perf      # EXCLUDE_FROM_ALL, must be named explicitly
```

`CURL_USE_LIBPSL=OFF` is the only intentional deviation (libpsl-dev not installed, `REQUIRED` when ON). Everything else is CMake defaults. Drop the flag if libpsl-dev gets installed.

Debugging: open `dev/` or repo root in VS Code; the launch config in `.vscode/launch.json` rebuilds `perf` and runs one test under gdb (the test name is its `args`).

## Profiling

Never profile the plain `./build` tree (`-O0`, no `-DNDEBUG`): inlining differs from `-O2` so hot-function attribution is wrong. Use a second tree:

```sh
cmake -S . -B build-relwithdebinfo -G Ninja -DCURL_USE_LIBPSL=OFF -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build-relwithdebinfo --parallel
cmake --build build-relwithdebinfo --target perf
```

Always pin to a core — WSL2 scheduling noise is ~106% run-to-run unpinned, <1-3% pinned:

```sh
taskset -c 3 ./build-relwithdebinfo/tests/perf/perf <test> [loops]
```

### `dev/perf2html.sh` — build + profile + report (every perf test)

```sh
dev/perf2html.sh                                     # generates `perf2html_baseline_report`.
dev/perf2html.sh -DCMAKE_C_FLAGS="-O3 -march=native" # generates `perf2html_modified_report`.
dev/perf2html.sh --report="~/try2"                   # generates `~/try2`
```

`dev/perf2html.sh [--verbose] [--keep-raw] [--regenerate] [--report=DIR] [cmake_flags...]`; `--help` prints the script's header comment. Key facts:
- `--regenerate` rebuilds `--report=DIR`'s pages from the raw data of its own last run and profiles nothing: `stamp_reuse` reads `stamp=` out of that report's `MANIFEST.txt`, checks every `dev/trace/` file that stamp names (callgrind, valgrind log, perf-stat CSV, speedscope JSON) and exits 2 listing what is missing; `build_manifest` reads `sampled`/`revision`/`cpu`/`build` back from the manifest instead of re-taking them, so the rebuilt report is byte-identical when no generator changed. Implies `--keep-raw`. Its log is `dev/trace/regenerate.<stamp>.<now>.log` — never the measurement run's `profile.<ts>.log`, which is itself reused raw data.
- `--keep-raw` keeps `dev/trace/`; without it the whole directory is deleted at startup, so raw data does not accumulate and nothing is left to regenerate from. Two runs with different stamps write disjoint filenames, so one `--keep-raw` batch leaves both reports independently regenerable.
- cwd-independent (cd's to `dev/`): a relative `--report=DIR` is `dev/DIR`, `~/` is expanded. Default DIR is `perf2html_baseline_report`, or `perf2html_modified_report` when any cmake_flags are given — after a *source* change alone, pass `--report=perf2html_modified_report` yourself. Last line printed is the report's `file://` URL.
- Build: `cmake -S .. -B build-relwithdebinfo -G Ninja -DCURL_USE_LIBPSL=OFF -DCMAKE_C_COMPILER_LAUNCHER=ccache <cmake_flags>`, then only the `perf` target. `-O2 -g` is prepended to a `-DCMAKE_C_FLAGS=` among the flags or added as one (`-DCMAKE_C_FLAGS=-O3` → `-O2 -g -O3`, the later flag wins). No `CMAKE_BUILD_TYPE`, hence no `-DNDEBUG` (curl's lib has no `assert`; only a `#error` guard mentions it). `CMakeCache.txt` is deleted before every configure, so nothing from a previous run's flags lingers. ccache is required: switching flag sets rebuilds 195 objects from cache in ~12s, same flags = configure only (~7s), no recompile.
- Trace tree: `build_compile` builds a second tree `build-instr` through the same `tree_build` — same flags with ` -finstrument-functions` appended to `CMAKE_C_FLAGS`, plus `-DCMAKE_EXE_LINKER_FLAGS="<repo>/build-instr/cyg.o -Wl,--export-dynamic"` (`cyg.o` = `cc -O2 -fcf-protection=none -c dev/cyg.c` — no `endbr64` in the hooks; the traced `perf` binary is deleted first, because ninja does not know `cyg.o` is a link input and would keep a stale recorder). The whole build is instrumented, lib and test code alike — no file list. glibc ships empty `__cyg_profile_func_enter/exit`, so every configure check links unchanged; the executable's exported copy wins at load time, so `libcurl.so` calls it too. Both trees ≈15s warm. `build-instr/` is ignored through `.git/info/exclude`, like `build-relwithdebinfo/`.
- No env vars — constants at the top of the script: `CPU=3`, `BUILD_DIR`, `TRACE_BUILD_DIR`, `LOOPS_DIVISOR=50`, `SKIP_ALL`, `MANIFEST_VERSION` (`perf2html_diff.sh` has `DIFF_MANIFEST`/`REPORT_MANIFEST`); `TESTS` is read from `tests/perf/Makefile.inc` (`TESTS_C`) and the callgrind/trace loops count is the test's own default / `LOOPS_DIVISOR` (`loops_of` greps `curl_off_t loops = N,` out of `tests/perf/<test>.c`) — no per-test case anywhere; the native timing run passes no loops argument (the test's default). Extra valgrind flags (LL cache auto-detects as direct-mapped and overstates conflict misses; `--LL=16777216,16,64` fixes it) go on the `valgrind` line in `run_one`.
- Profile: `taskset -c 3 valgrind --tool=callgrind --cache-sim=yes --branch-sim=yes` (1-18s per test). Events: `Ir Dr Dw I1mr D1mr D1mw ILmr DLmr DLmw Bc Bcm Bi Bim`. Timing: separate native pinned run under `perf stat -x, -e cycles:u,instructions:u` (counting mode, no sampling) — its `Time*` lines are the only valid speed number; callgrind's own wall-clock is never used as one. `Cycles:`/`Instructions:` lines are appended to `perf-tool/output.txt` from the CSV (`dev/trace/perf-stat.<test>.<ts>.csv`), and the overview turns every `Label: value` line of that file into a column.
- Trace (`trace_render`): two pinned runs of `build-instr`'s binary at the callgrind loops count. Run 1 (`CYG_SKIP=$SKIP_ALL`) only counts enter/exit events; run 2 (`CYG_SKIP=<count/2>`) keeps the `MAX_REC` (16384) events after the run's midpoint — warm, inside the test's loop, no cold start or teardown. `trace_to_speedscope.py` cuts that to the flame graph's slice, `build_flame_graph.py` loads it into a fresh copy of the speedscope bundle. Everything the two runs and the converter print goes to `<test>/flame-graph/output.txt` (run stamp and `dev/trace/` prefix stripped) = the summary's "trace log". ~1s per test.
- Validates nothing itself: `dev/perf2html_batch.sh` is the only caller of `validate_report.py`. Same for `perf2html_diff.sh`.
- Everything the tools print goes to `dev/trace/profile.<ts>.log` (quiet mode) or the terminal (`--verbose`); a failing step shows its last 40 lines.

Naming scheme across `dev/`: `object_method`-style lowercase C-identifier form (e.g. `args_parse`, `theme_css`, `profile_parse`, `report_test`) for shell functions and for a script's public free functions; a method inside a class drops the object prefix its class already supplies (`Callgrind.parse`, `BuildReport.report_page`, `ValidateReport.page_check`). Each script's entry point is `main()`, defined at the bottom of the file directly above `if __name__ == "__main__":`. Follow this for any new top-level Python/shell function. Embedded JS in generators' HTML templates is untouched by this rule.

Raw data in `dev/trace/` (gitignored): `callgrind.out.<test>.<loops>.<ts>`, `valgrind.<test>.<loops>.<ts>.log`, `trace.<test>.<loops>.<ts>.bin` (+`.maps`, its `/proc/self/maps`), `trace.<test>.<loops>.<ts>.speedscope.json`, `perf-stat.<test>.<ts>.csv`, `profile.<ts>.log` (quiet mode only). Every path embedded in a generated page is relative — OUTDIR is portable.

**Generated pages are deterministic**: same input ⇒ byte-identical output, so a page diff is always code, never sampling. The only timestamp that reaches a page is `MANIFEST.txt`'s `stamp=` row (the run's `<ts>`, shown as a header column, and what `--regenerate` reuses); a *re*-generation of one report reproduces it exactly, so pages stay byte-comparable — it varies only when the data was actually re-measured. Otherwise `dev/trace/` keeps the `<ts>` for run history, but the copy under `<test>/raw/` drops it (`callgrind.out.<test>.<loops>`, `callgrind.diff.<test>`) because the summary prints that basename as link text, `MANIFEST.txt` has no `generated=` row, and the speedscope document name (`--name`, also what `build_flame_graph.py` shows, read from the JSON's own `name`) is stamp-free. The only run-to-run variation is measured time: `perf-tool/output.txt`, `flame-graph/output.txt` and the trace itself (`flame-graph/profile.js`, `raw/trace.*.json`) — `trace_to_speedscope.py` is still byte-deterministic on one `.bin`. Check with: run any generator twice on one input and `cmp`.

### `dev/perf2html_diff.sh` — compares two reports

```sh
dev/perf2html_diff.sh                             # `perf2html_baseline_report` vs `perf2html_modified_report` -> `perf2html_diff_report`
dev/perf2html_diff.sh ~/before ~/after            # -> `perf2html_diff_report`
dev/perf2html_diff.sh ~/before ~/after ~/delta    # -> `~/delta`
```

`dev/perf2html_diff.sh [--verbose] [--keep-raw] [--regenerate] [baseline-dir modified-dir] [report-dir]` — 0 dirs = the defaults, 1 = report-dir, 2 = baseline modified, 3 = all; flags before the dirs, in any order (`args_parse` loops); relative dirs under `dev/`, `~/` expanded; `--help` prints the header comment. Key facts:
- This script measures nothing — it subtracts the two reports' own `raw/` data — so `--regenerate` only reuses the `stamp=` of its previous diff (read back from its own `MANIFEST.txt`) instead of taking a new one, keeping its `dev/trace/` filenames stable across re-runs. `--keep-raw` keeps `dev/trace/`; without it the directory is deleted at startup. Both flags exist mainly so `perf2html_batch.sh` can pass one set of flags to all three scripts.
- Inputs are two `perf2html.sh` OUTDIRs, recognized by the **first line** of `MANIFEST.txt` alone (`manifest_check` reads it with `head -1`, never the whole file, since the header rows follow: a diff report's own version string names `perf2html_diff.sh`, so a diff can't be diffed; a report predating the manifest must be regenerated). Tests are paired by directory name (`tests_pair`); a test only one side has is noted on stderr and skipped.
- Output: mirrors the input layout — `index.html` (overview) + `<test>/index.html` + `<test>/heat-map/` + `<test>/raw/callgrind.diff.<test>` + `README.md` + `MANIFEST.txt` (its own version line + `baseline`/`modified`/`stamp` rows). **No flame graph, no native timing** — two recordings don't subtract, and neither do two wall clocks.
- The overview's header is a `baseline` and a `modified` block (`--header-block LABEL=FILE`, one `<h2>` + header table each) holding that side's `report=` directory followed by its own `MANIFEST.txt` header rows, so the diff page shows the same build/timed stats as the two reports it came from. `header_file_of` in the diff script writes each block's file to `dev/trace/header.<role>.<ts>.txt` (`grep '='` on the source manifest, so its version line never becomes a row); a source report whose manifest is the version line alone contributes its directory alone. Every directory/file path written into a header block or the diff's own `MANIFEST.txt` (`baseline=`/`modified=`) goes through `path_display()` (`os.path.relpath` against `$PWD`, i.e. `dev/`) first — never the raw absolute path — so nothing under `$HOME` reaches a page. **A per-test diff page has no header table and no raw-data link** — `diff_one` no longer passes `--header baseline=/modified=` or `--raw-data` to `build_report.py test --diff`, so the page goes straight from the strip to "top N functions by change in self"; only the overview's `baseline`/`modified` blocks above still show those file paths, and the delta callgrind file still lands in `<test>/raw/` (used by `raw_dir_check`), just with no on-page link to it.
- Every number is MODIFIED − BASELINE, **per source line**: `callgrind_diff.py` parses both sides with the shared parser, subtracts per (function, file, line) via `Profile.function_lines` — never per (file, line) alone, which hands roughly half of an inlined function's cost to its neighbour (`line_function` is first-seen) — and writes a plain callgrind-format file: `fl=`/`fn=`/`fi=` per function, that function's entry line first (a zero-cost line if it did not change), `summary:` = the signed total so the 1.0000 self-check holds on the delta too. No `calls=` lines in the delta file itself: it has no call graph, hence no call columns/caller tables in the heat map (`HAS_CALLS`). The summary table's calls/callers columns are a separate synthesis: `CallgrindDiff.callers_subtract()` diffs the two source profiles' own `Profile.callers` in memory (never written into the callgrind-format delta) and `-o DELTA`'s sibling `--callers-output FILE` writes it as its own JSON sidecar (`{event, callers: {callee: [[caller, count_delta, cost_delta], ...]}}`), consumed only by `build_report.py test --diff --callers-data FILE`.
- Shares use the **sum of all magnitudes** as denominator (`callgrind_diff.profile_magnitudes()` = Σ|per-function line delta|, the finest granularity, so no line or function share exceeds 100%), not the near-zero signed total. Summary table and both heat-map home tables rank by `abs()`, so biggest winners and losers interleave at the top; heat intensity is `abs()` too. Heading is "top N functions by change in self"; `HOT` becomes "Most changed".
- Ranking event is `Ir` (`build_report.EVENT`); the heat map's event picker still offers every event. Delta header: `desc: Baseline: <file>`, `desc: Modified: <file>`; the repo root is stripped from every written path.
- `dev/trace/callgrind.diff.<test>.<ts>` + `callgrind.diff.<test>.<ts>.callers.json` (the caller-delta sidecar, `callgrind_diff.py --callers-output`) + `diff.<ts>.log` (quiet mode).

**Core vs diff code.** The non-diff path is byte-for-byte checkable against an older generator (build both from one `raw/` file with `git show <rev>:dev/scripts/*` copies and `cmp`). `build_report.py`: `BuildReport.test`/`.functions_table` are core, `.diff_test`/`.diff_functions_table` are the diff, both through `.report_page()`; `--diff` only picks the method in `main()`. `callgrind_to_heatmap.py`: `CallgrindToHeatmap.model()` is core, `.diff_model()` patches `meta.totals`/`meta.diff`; in its JS every diff override sits in the one `if (DIFF) {...}` block (`fmtP`/`fmtH` wrapped with a sign, `HOT`/`HOT_LINES`/`SELF.title`), and ranking/heat go through `mag()` (= `Math.abs`, a no-op on a profile's non-negative costs). `validate_report.py` is data-driven by `Layout` (`LAYOUT_FULL`/`LAYOUT_DIFF`, picked by `--diff`).

### Scripts (`dev/scripts/`)

Every CLI below is invoked only by the three shell scripts (`perf2html.sh`, `perf2html_diff.sh`, `perf2html_batch.sh`); the signatures here are the checklist of what each still takes (`--help` on any of them lists its arguments).

**File shape, every script.** Constants first, then classes, then the cross-script public API as free functions, then `main()` last (directly above `if __name__ == "__main__":`). Each script has one enclosing class named after it in PascalCase (`Callgrind`, `BuildReport`, `CallgrindDiff`, `CallgrindToHeatmap`, `TraceToSpeedscope`, `ValidateReport`, `CheckJs`, `BuildFlameGraph`; `theme.py` splits `Theme` + `Numbers` + `Palette`, which are distinct concerns) holding **every** function the script does not export — no free helpers, no nested `def` closures. A second class only where it carries state of its own (`CallgrindToHeatmap._FileAccumulator`/`._LineAccumulator`, `Callgrind._NameTable`/`._Positions`/`._PendingCall`); a plain transform stays a method. Classes are alphabetical within two bands — record types (`NamedTuple`/`TypedDict`/`@dataclass`) first, then logic classes — and methods are alphabetical inside every class. Public free functions are thin one-line delegations (`profile_load(paths)` → `Callgrind().load(paths)`), so callers and the shell scripts never name a class; keep them that way when adding one. Module singletons exist only where a class is called constantly (`theme.PALETTE`/`NUMBERS`/`RENDERER`).

- `callgrind.py` — the one parser: per-line/function cost vectors, call graph. `profile_load(path)` parses one file and exits unless the self-check ratio (printed to stderr) is 1.0000. `REPO_ROOT` (from the script's own location — no `--repo-root` flag anywhere) and `path_norm(path) -> PathInfo(display, local, group)` are the one path resolver every generator uses (`local` is None unless the file is readable; `group` is repo/system/external). Functions keyed by **name** (not object), so a symbol in two objects is one function. Derived events added when inputs exist: `D1m`, `DLm`, `L1m`, `LLm`, `Bm`, `CEst` (= Ir + 10·L1m + 100·LLm). Tables are keyed by NamedTuples (`SourceLine`, `CallSite`, `Caller`), call-graph edges are `Tally(count, costs)`. `Profile.function_lines[fn][SourceLine]` is the only per-context table (`line_self` merges every `fn=` context a line was charged under). A function nobody recorded a call to gets `function_entry` from the **first** cost line callgrind wrote for it in its home file — that matched the `calls=` target line in 505/505 checked functions; the lowest line number does not (inlined helpers sit above the entry).
- `theme.py`/`theme.css`/`theme.js` — shared look/behavior, inlined by every generator (see "Look and feel").
- `build_report.py test FILE -o OUT --test TITLE --raw-data FILE [--log FILE] [--perf-log FILE] [--trace-log FILE] [--diff] [--callers-data FILE] [--header LABEL=VALUE]...` — the summary page; both plain and `--diff` render a "#, % self, symbol, ir, calls, callers" table (ir = the ranking event, `EVENT = "Ir"`). `--perf-log FILE` reads the perf tool's captured stdout (`perf-tool/output.txt`) into a collapsed "perf log" section above "valgrind log", and `--trace-log FILE` (`flame-graph/output.txt`) into a "trace log" section between them — the flame graph strip link exists only when `--trace-log` is given (`FLAME_VIEW`), so a page without a trace cannot link one (both `BuildReport.output_section`; empty/omitted path renders nothing, same for `--raw-data`/`BuildReport.rawdata_section` with no paths) — there is no more standalone timing page or `perf-tool` strip view. `perf2html.sh`'s `report_render` omits `--perf-log`/`--trace-log`/`--raw-data` (and passes `--no-log`) only for the "all" synthetic test, so its summary page goes straight from the strip to "top N functions" like a diff page does; every other test still gets all four sections. `--diff` dispatches to `BuildReport.diff_test` (abs ranking, signed numbers, `HEAT_VIEW`-only strip, no `--header`/`--raw-data`/`--log`/`--perf-log` preamble — a diff has no perf-tool run of its own). its calls/callers columns come from `--callers-data FILE`, a `callgrind_diff.py --callers-output` JSON sidecar (empty/blank cells if omitted). `build_report.py overview -o OUT --test NAME... [--header LABEL=VALUE] [--header-file FILE] [--header-block LABEL=FILE] [--diff]` — the cross-test page, its "test suites" table columns still read straight from each test's `perf-tool/output.txt` (`BuildReport.overview`); `--header-file` appends a file's `LABEL=VALUE` lines to the `--header` rows and silently drops every other line (that is how `MANIFEST.txt` reaches the page, version line and all), `--header-block` adds a further table under its own `<h2>` from such a file (repeatable; the diff's baseline/modified blocks — unaffected, still only on the overview page), `--diff` swaps each test's native timing for its `Ir` change. **"header" = the label/value rows above a page's real content** (`Header`/`HeaderBlock`, `BuildReport.header_table`/`.header_read_file`/`.header_parse_blocks`) — not the heat map's `MetaModel`, which is a profile's event metadata. `EVENT = "Ir"` and `TOP = 50` are constants.
- `callgrind_diff.py --baseline FILE --current FILE -o DELTA --callers-output FILE` — subtracts per (function, file, line), writes a callgrind-format delta (see perf2html_diff.sh above). `--callers-output` is required: writes the per-(callee, caller) count/cost delta JSON described above, ranked `(-abs(cost), -abs(count), name)`. Also home of `profile_magnitudes()`, which the generators import.
- `callgrind_to_heatmap.py FILE -o OUT --title T [--diff]` — heat-map/index.html; `DEFAULT_EVENT = "CEst"`, `TREE` = the directories whose tracked `.c/.h` files are listed even without samples. `--diff` = `CallgrindToHeatmap.diff_model()`: shares against `profile_magnitudes()`, signed numbers, "Most changed" headings (the JS `if (DIFF)` block). Call columns and the popup's caller table/note exist only when the profile has a call graph (`HAS_CALLS`).
- `dev/cyg.c` — the recorder, linked into `build-instr`'s executables: while sampling a hook is only `if(next < end) { next->fn = fn; next->tsc = rdtsc | flag; ++next; }` — 11 instructions on enter, 12 on exit (was 28/29; check with `cc -O2 -fcf-protection=none -S -masm=intel dev/cyg.c`). `next` is a pointer (an index into `buf[]` costs 4 more) and `end` a variable set by the constructor (as a constant address it costs a PIE a `lea`). `next == end` = not sampling, and everything else lives on that path (`cyg_idle`, cold): counting unrecorded events (`idle`; header `seen` = `idle` + kept) and opening the window after `CYG_SKIP` of them. Whenever `next == end`, `final` is where sampling stopped (`buf` = not opened yet, `end` = buffer full). `cyg_pause()` (`final = next; next = end`) / `cyg_resume()` (`next = final`) switch sampling off and on and nest through `holds` — the window opener owns the first hold, the destructor takes the last; both are `static` until something outside calls them. Setup is a constructor (env, `memset` of the static `MAX_REC`-record buffer so no page fault lands in a timed call, t0 clock pair), so no hook ever checks for it; records are `{function address, rdtsc | EXIT_BIT}`; a destructor writes `CYG_OUT` = `uint64[8] {MAGIC, kept, seen, skip, t0_ns, t0_tsc, t1_ns, t1_tsc}` + records, and `CYG_OUT.maps`. `CYG_OUT` unset = `next == end == NULL`, nothing is ever recorded. Single-threaded, like the perf tests. The header comment there is the format's reference.
- `trace_to_speedscope.py TRACE -o JSON --name NAME` (`--seen` prints the run's event count for `perf2html.sh` and writes nothing) — trace → speedscope evented profile. `TraceToSpeedscope.calls()` pairs enters with exits (any mismatch exits non-zero); an exit with nothing open closes a frame entered before the window and starts a new sibling run; the run with the most events wins (mid-run that is the test loop's direct calls) and its first `MAX_CALLS` = 10 complete calls are emitted, fewer if the JSON would pass `MAX_BYTES` = 10240 (one call is always emitted, with a warning if it alone is over). `at` = `round((tsc - t0_tsc) / tsc_per_ns)`, `tsc_per_ns` from the header's two clock pairs — raw, nothing subtracted, the hooks' own cost included. Frames: address → `.maps` mapping → `readelf -lW` LOAD segment → `addr2line -f -C`, file through `callgrind.path_norm()`; GCC instruments inlined bodies, so inlined helpers are frames too. Must run while `build-instr` still holds the traced binary. Profile name = tool + event range (`events A..B of N`); `exporter` = the script's path, which `validate_report.py` checks.
- `build_flame_graph.py --speedscope-dir DIR --profile-json JSON` — plain loader: writes `profile.js` (base64 of the JSON + `loadFileFromBase64`), patches a fresh `index.html`, document name from the JSON's `name`.
- `validate_report.py OUTDIR [--diff]` — structural smoke test, called only by `perf2html_batch.sh` step 5 (pages exist/non-truncated, titles, strip links, `raw/` has a callgrind file without the absolute repo root, timing line present); `flame_graph_check` decodes `flame-graph/profile.js` and requires exactly one `evented` profile whose `exporter` is `FLAME_EXPORTER` (a synthesized or stale flame graph fails), plus `flame-graph/output.txt` and the "trace log" section — for every test but "all", where `flame-graph/`, its strip link and the section are all forbidden (`index_check` tests the link both ways); an `overview`-titled index also walks every test directory it links to. `home_dir_check` walks every file under `OUTDIR` and fails if `os.path.expanduser("~")` (the author's `$HOME`) appears anywhere — not just MANIFEST.txt, since `perf-tool/output.txt` echoed the binary's absolute path until `perf2html.sh` started passing `BIN_REL` there too; a report is meant to be copied around and must not name the machine/user it was made on. `MANIFEST.txt` is checked at the root: first line = `Layout.manifest_version`, plus a `LABEL=` row per `Layout.manifest_labels` (full: sampled/revision/cpu/build/executable/stamp; diff: baseline/modified/stamp). `--diff` = heat map only, "by change in self" heading, overview must carry the `baseline`/`modified` header blocks (`Layout.header_blocks`). `Layout.test_has_rawdata` (full: true, diff: false) gates whether `perf_tool_check` runs at all (full only: `perf-tool/output.txt` sanity; a diff has no perf-tool run). Within a full report, `test_report_check` further ANDs it with `name != "all"` (`has_rawdata`/`has_perf_log`) before checking the per-test index's "raw data"/"perf log" sections both ways — required for every test but "all", forbidden for "all" and for any diff page (the diff per-test preamble was dropped; only `raw/` itself, checked separately by `raw_dir_check`, still exists for every test including "all").
- `check_js.py` — `node --check` on `theme.js` and on every JS chunk embedded in a generator's Python string (`SOURCES` lists the module/attribute pairs; `<script>` blocks that are only a `__PLACEHOLDER__` are skipped). Add a pair here when a generator grows new embedded JS.

`callgrind.py`'s parser prints a self-check ratio to stderr on every run — must be exactly 1.0000 or nothing is written; re-verify it after touching the parser. It is cost conservation only and says nothing about whether an emitted structure was ever observed (rule 6).

`dev/scripts/*.{py,js,css}` carry **no comments or docstrings** — none in the Python, none in the JS/CSS embedded in its string literals, none in the standalone `theme.js`/`theme.css`. Symbol names are the only documentation; behavioral notes belong here or in `dev/README.md`. Keep new edits comment-free. Shebangs stay. `argparse.ArgumentParser()` gets no description, so `--help` lists only the arguments by design.

### `dev/perf2html_batch.sh` — every check the tooling has, one run

```sh
dev/perf2html_batch.sh                          # lint, both reports, the diff, validate all three
dev/perf2html_batch.sh --keep                   # don't delete the three report dirs first
dev/perf2html_batch.sh --keep-raw               # keep dev/trace/, so a later --regenerate works
dev/perf2html_batch.sh --regenerate             # rebuild all three reports' pages, profile nothing
dev/perf2html_batch.sh -D CMAKE_C_FLAGS=-O3     # the modified build's flags
```

`dev/perf2html_batch.sh [--verbose] [--keep] [--keep-raw] [--regenerate] [cmake_flags...]`; `--help` prints the header comment. Five steps, in order: **1 lint** (pyright over `dev/scripts` per `dev/pyrightconfig.json` — `standard` mode, `pythonVersion` 3.11, must stay at **0 errors** — plus `check_js.py`, which catches a `\n` that needed `\\n` in JS-inside-a-Python-string before it reaches a generated page), **2 baseline** (`perf2html.sh` → `perf2html_baseline_report`), **3 modified** (`perf2html.sh <flags>` → `perf2html_modified_report`, default flags `-D CMAKE_C_FLAGS=-Os`), **4 diff** (`perf2html_diff.sh` → `perf2html_diff_report`), **5 validate** (`validate_report.py` on all three, `--diff` on the last). Key facts:
- The three report dirs are **deleted before step 2** (`--keep` skips it) so a stale page can't be validated in place of a fresh one; ~2.5min for a full run (two builds + two callgrind passes).
- `--keep-raw`/`--regenerate` are forwarded to steps 2, 3 and 4 unchanged; `--regenerate` also implies `--keep` (`reports_clean` would delete the very manifests holding the stamps). **The batch owns every `dev/trace/` deletion**: with neither flag it deletes the directory at startup (before opening its own log there) *and again after step 5*, so a clean flagless run ends with no raw data at all, and it passes `--keep-raw` down so the three children never delete it mid-run (a child deleting it unlinks the batch log, and the next `>>` silently recreates it, losing every earlier step's output). **Exception: a failed flagless run keeps `dev/trace/`** and says so, since the step logs it holds are the evidence. Steps 2 and 3 take separate stamps, so one `--keep-raw` run leaves both reports regenerable.
- Every step runs even if an earlier one failed — one run reports every broken thing, not just the first. Exit 1 if any failed, and the closing line names them (`perf2html_batch: N step(s) failed: ...`). Last line on success is the diff report's `file://` URL.
- **Step 5 is the only `validate_report.py` call anywhere**; `perf2html.sh`/`perf2html_diff.sh` validate nothing. Keep it that way — don't re-add a validate step to a generator.
- Quiet mode logs each step to `dev/trace/perf2html_batch.<ts>.log` and prints the last 40 lines of a failing one; `--verbose` streams everything and is passed down to both generators.
- `cmake_flags` go to `perf2html.sh` untouched. Both cmake spellings work and keep their form: glued `-DCMAKE_C_FLAGS=-Os` and separated `-D CMAKE_C_FLAGS=-Os` (two argv words) both get `-O2 -g` prepended in place by `args_parse`; `CMAKE_CXX_FLAGS` does nothing here (curl is C).
- **This is where the generators are tested.** Driving them over all three output directories is their coverage — neither runs a check of its own, and neither should grow one.
- Replaced `dev/lint.sh` (deleted — its pyright/check_js body is step 1); named `dev_test.sh` for one commit before the `perf2html_*` rename.

The checker is **pyright**, installed from PyPI: `pip3 install --user --break-system-packages pyright` → `~/.local/bin/pyright` (this box is PEP-668 externally-managed and has no pipx/uv; the flag matches how the other `~/.local/bin` tools got there). **Pylance is not usable here** — it is a VS Code extension, and its bundled `dist/pyright.bundle.js` speaks LSP only, ignores argv and prints nothing (no `outputjson` string in it).

Typing rules in `dev/scripts/` (everything annotated, no `Any`-shaped records): a record is a `NamedTuple` (`callgrind.SourceLine`/`Term`/`DerivedEvent`, `theme.Column`/`Cell`/`ColorPair`, `build_report.View`/`StripLink`, heat map `LineCost`/`CallRow`); anything summed in place is a `@dataclass` (`Profile`, `Tally`, heat map `CallgrindToHeatmap._FileAccumulator`/`._LineAccumulator`). JSON-bound shapes: an object is a `TypedDict` (`HeatModel`/`FileModel`/`FunctionModel`, `SpeedscopeDoc`, `ThemeRuntime` — a NamedTuple would serialize as an array), a positional array is a NamedTuple (`json.dumps` writes it as the `[a, b, c]` the page indexes). Cost vectors are `callgrind.Costs` (`list[int]`), summed only via `costs_add`/`costs_accumulate`/`tally_accumulate`. Each CLI turns argparse into a NamedTuple (`TestArgs`, `HeatArgs`, `TraceArgs`, ...) before calling anything. Naming: a field that would shadow a method of its base class gets a trailing underscore, never a synonym — a NamedTuple's `index`/`count` (pyright: overrides `tuple`'s methods) is `index_`/`count_` (`ResolvedTerm.event_index`, `LineCost.count_`, `CallRow.count_`); a dataclass field with the same meaning stays plain (`Tally.count`). Generator output is reproducible run to run (the heat map's `CallgrindToHeatmap.model` walks raw file names sorted, so the `raw` field of an external header that several build paths map to is always the same one); byte-compare generated pages directly.

### Line-level view (why the heat map exists)

Under `-O2` small static functions inline into their callers, so the function-level top-N table charges their cost to the caller. The heat map shows it per source line; the flame graph shows inlined bodies as frames of their own. Cross-check with:

```sh
callgrind_annotate --show-percs=yes dev/trace/callgrind.out.<test>.<loops>.<ts> <file>
```

`/* perf #N: X.XX% */` comments in `lib/` are dev annotations from an old profile — drop before submitting upstream.

### Look and feel (theme rules — apply to any dev/ page changes)

- One dark theme. `theme.py`'s `COLOR_PAIR` values are raw "User settings" THEME entries, odd index = dark member, even = light; `--<name>-l` is the light member. Don't touch the `HEAT` ramp with this rule. Exception: `--bg` (`ROLE["bg"]`) is the slate dark member darkened 8% via `Palette.shade()` (`#2F3640` → `#2B323B`); every page background, the scrollbar track, the minimap band and the heat blend (`heat_style()`/`heatStyle()` via `theme_runtime()`) all follow it, so change it only there.
- Monaco/monospace everywhere; column widths are exact `ch` counts: the header label is every column's floor (a header never ellipsizes, and **no column is ever narrower than its own title** — not at rest, not after a drag, not after a fill), then the longest cell text; `width` = exact floor, `clip` = cap; + `theme.PADDING_CHARS` (1ch padding each side + 1ch slack). Every column shrink-to-fits by default, the `grow` column included. One rule in two places — `colWidths()` in the heat map's script and `table_render()` in theme.py — keep them in step. Both emit `data-min="<label+PAD>ch"` per `<col>`; theme.js's `floorPx()` resolves it to px (hidden probe div, `MIN_COL` = 24px absolute floor) and both the drag clamp and `fillTable()` use it, so nothing can be squeezed to 0 and every title stays visible.
- Heat colors: 12-stop `HEAT` ramp blended over `--bg`, alpha on log scale of magnitude; text color picked by resulting luminance (`theme.heat_style()` / `heatStyle()`). Non-diff pages index it single-ended, `0..1` low-to-high (unchanged). Diff pages index it signed, `-1..1` across the *whole* ramp — negative (savings) toward `HEAT[0]` (cold/blue end), positive (regressions) toward `HEAT[-1]` (hot/red end), 0 at the ramp's midpoint — via `heat_style(heat, signed=True)` / the JS `if (DIFF)` branch inside `heatStyle`/`heatP` (`(heat+1)*0.5` remap before indexing; sign no longer stripped before the call). Only caller needing `signed=True` today: `diff_functions_table`'s "% self" column; the heat map's `heatT`/`heatP` auto-detect via the module-level `DIFF` const. Speedscope keeps its own colors (untouched by theme).
- No decorative borders anywhere. The only drawn lines are drag targets: column-resize `.bar` and pane `.split`, both invisible at rest and painted only on hover/active (`.bar::before`/`.split` background is `none` until `:hover`/`.active`). Everything else is told apart by background shading only (`--panel`/`--bg`/`--bg-alt`/`--nav`). `select`/`input` get `border:0; border-radius:0` + explicit `--bg`.
- A `<select>` whose option text length varies with page state (heat map's `#event`, long name changes per event) gets a fixed `style.width` in `ch` sized to its longest option + slack at populate time, so picking a different option never reflows sibling controls.
- Scrollbars: square unrounded `--blue` thumb, 14px, no arrows, track = pane's own `--bg` (exception: `pre.logbox` matches `--panel`). No hover/active state on the thumb itself.
- Every table is `theme.table_render()` / heat map's `table()`: draggable resize bar at every column boundary including the trailing edge. Column widths are **never persisted** — reload always resets to default; "reset columns" link (top-level strip only) undoes drags for the current view only, and also clears any `Theme.splitter` pane (heat map's tree/source split, `localStorage["split.heat.tree"]`) back to its authored width — `Theme.resetCols` tracks every `splitter()` pane in a module-level list and resets those under its `root` alongside `table.cols`; the heat map's `theme:reset-cols` handler calls `Theme.resetCols()` with no root (whole document) because `#tree` sits beside `#main`, not inside it. Probe (Chrome, `--allow-file-access-from-files`, outer page at `#<test>/heat-map/f=<file>`): drag the listing's trailing `.bar` and `#split`, click the summary strip's "reset columns" — `#tree` must read 280px again and `table.src` width must equal `#main.clientWidth`. `fill` tables (overview/summary header tables, summary functions table, heat map's per-file source listing) end with their right edge at the **same inset from the scrolling pane as their left edge** — `fillTable()` measures that left inset live and targets `clientWidth − 2·inset`, so there is no fill fraction and no `data-fill` attribute (`scrollerOf()` in theme.js: nearest `overflow: auto|scroll` ancestor, else the document — never `window.innerWidth`, the heat map's listing pane is only part of the window). The source listing sits in a pane with no padding, so its inset is 0 and it still runs edge to edge between tree and minimap. Floored to whole px so rounding can't raise a sideways scrollbar; the `grow` column (`<col class="grow">` — heat map `col.grow`, theme.py `Column.grow`; else the last) takes the rest. **Every column, grow included, is shrink-to-fit server-side** (`colWidths`/`table_render` measure the grow column's cells like any other), but its runtime minimum (`data-min`, `floorPx()`) is the **title width alone** — never the authored width — so `fillTable()` squeezes the grow column down to its title before a pane ever scrolls sideways and the listing's right edge lands on the pane's edge at rest (1366×768: `table.src` = `#main.clientWidth` = 932px with the tree at 280px). The source column keeps `width: SRC_COLS` = 80 as a floor under its measured (authored) width only. `fillTable()` re-fits on every `Theme.relayout()` (window resize, tree splitter drag — one rAF per move) until a column bar is dragged (`table._dragged`); "reset columns" clears that and re-fits. `fillTable()` returns at once for a table with no layout (`offsetWidth` 0): under `display:none` every rect and `clientWidth` reads 0, so it would fit the grow column to `0px` — the frame's `home` is hidden behind the iframe, and a window resize / "reset columns" / a load with `#<view>` in the URL used to leave the summary's `callers` column at 0px. Frame `show()` calls `Theme.relayout(home)` on every return to the summary, so whatever changed while hidden is fitted then (probe: `col.style.width`/last `th` width must be >0 after `#heat-map` → `resize` → summary). The trailing `.bar` lies wholly inside the table (`.bar:last-child`, line flush with the right edge) so a 100% table never pokes past its pane. Heat map's two home tables ("Hottest lines by"/"Hottest functions by") are plain (non-`fill`) tables sized to content, same as the tree pane, so a long column header can't stretch a heat-colored value cell into a wide bar or push a trailing column off-screen. No per-column tooltip is a "legend" link anymore — glossary lives once in README.md. Full row is a click target on `fill`/rowlink tables; only the one real `<a>` cell shows hover state.
- Numbers: `theme.num_human()`/`fmtH()` → `2.1K`/`21K`/`2.1M`/`2.0G` (exact value in tooltip); shares via `theme.num_pct()`/`fmtP()` → `63.2%`, `<0.01%`. Diff pages wrap both in a sign: `theme.num_signed()`/`num_signed_pct()` and the JS `fmtH`/`fmtP` overrides in the `if (DIFF)` block → `+4.3K`, `−37.8%` (U+2212 in the page, exact zero renders as empty, not `+0`; `fmtH(0)` is `0`).
- Index page is a frame: strip (title badge + `|`-separated plain-word links, no brackets, `flex-wrap: nowrap` so it clips rather than wraps) + its own page; sub-pages load into an iframe on click. Picked link/title highlighted at `--hot`/`--hot-fg`. Title = current view path (`<test> / heat map`). `theme.TITLE_COLUMNS` sets `--title-w` and must stay ≥ the **widest title any page can show** — `len("simpleformat diff / flame graph")`, i.e. the longest `TESTS_C` name + the longest view label + the diff suffix; too small and the badge silently clips mid-word (`flex-wrap: nowrap`) on exactly the one test/view pair nobody opens. "reset columns" / "help" / "curl.se/perf" sit right-aligned via `.strip .sp`.
- Frame pages nest two deep: the overview frames a test summary, which frames that test's heat map / flame graph (`FLAME_VIEW`/`HEAT_VIEW` — no more separate native-timing view/page; its output lives in the summary's own "perf log" section) (the heat map's `#hdr` is a controls strip, not a frame strip). Both `FRAME_JS` levels are the same script, which decides by `framed = window.parent !== window` and by `data-frame` on the active strip link (set for the overview's per-test links, `StripLink.frame`):
  - **Title badge**: printed only by the outermost strip (`setTitle` writes `""` when `framed`). The badge element stays, so it reads as one continuous `--title-bg` block down the stacked strips and every strip's links line up at `--title-w`. `document.title` is still set at every level.
  - **Util block** (`#util`: "reset columns | help | curl.se/perf"): lives on the lowest strip that has one. A framed page always shows it; a top-level page hides it (`util.hidden`) only while it frames another frame page, which brings its own. A single-test report opened on its own therefore keeps it on its top strip.
  - **"reset columns"** walks the whole nest: each level resets its own `home` and posts `theme:reset-cols` down (`resetAll()`), and a framed page runs `resetAll()` when it receives that message from `window.parent`, so the click reaches all three documents. Probe both with the Chrome `probe.html` trick (a framed `contentDocument` is same-origin only with `--allow-file-access-from-files`).
- URL = the whole state, one grammar at every level. Frame page (`FRAME_JS` `parse()`/`build()`): `#<view>[/<inner hash without #>]`, e.g. `#heat-map/f=<file>&l=<n>&e=Ir`. Heat map (`hashOf()`/`stateOf()`): `f=<file>` file, `f=<file>&l=<n>` line (popup open), `fn=<name>` function (popup at its entry line), none = home; `&e=<event>` always spelled out when the profile has >1 event; `enc()` percent-encodes values but keeps `/` readable. Every click is `location.hash =` (one history entry per step, back/forward walk them); `route()` renders it, then rewrites the canonical spelling via `replaceState` (unknown file/function → home, unknown line → its file, unknown event → default) and posts `{theme:"hash", hash}` up; `FRAME_JS` `sync()` mirrors it into `#<view>/...` via `replaceState`. Closing a popup ([X], "close", re-clicking its row) navigates to `hashFor(curFile)` = the file. `fn=` links: summary symbol/caller cells (`entry_link()`, `urllib.parse.quote` with encodeURIComponent's safe set + `/`), home "Hottest functions" rows, popup callee "defined at" (`linkFn()`/`fnLinkable()`); `f=&l=` links: hottest lines, chips, popup caller "called at". Bare `#heat-map` = home at the default event — nothing is remembered outside the URL (`heat.event` localStorage is gone); scale/sort/search stay `localStorage`-only (`heat.scale`/`heat.sort`).
- Render is a function of the hash: `route()` rebuilds the listing only when the `shown` key (file, event, scale) changes — a rebuild of the same file keeps `scrollTop`, a new file without `l` centers its hottest line — then `detailSet(line)` reconciles the popup (`detailOpen()`; the popup under the row is the only marker of the picked line — no outline/recolor on the row; the row is centered only if `rowOnScreen()` is false, so a clicked row stays put while a chip/link/bookmark scrolls to it). Scale change: `shown = ""` then `route()`; event pick: `location.hash = hashOf({...state, ev})`.
- `FRAME_JS` puts a page into the frame with `view.contentWindow.location.replace(href + (sub || "#"))` — never `iframe.src`, which adds a joint history entry per load so back would desync strip and frame (headless Chrome check: `history.length` +1 per hash step, +0 per frame load, back/forward restore both levels). `"#"` not `""` for the empty state: a fragment-less URL is a document reload, `#` a fragment navigation. Same page and same `state` → nothing. Four messages, all checked by source (`event.source === view.contentWindow` inward, `=== window.parent` outward). **inner→outer**: `{theme:"hash"}` — posted by the heat map's `syncHash()` **and** by `FRAME_JS`'s own `sync()` when `framed`, so a middle level relays its full `#<view>/<inner>` upward and the outermost URL tracks menu + file + line + event (without it the outer hash freezes at `#<test>` and a reload loses everything below it). `sync()` always posts the hash it just canonicalized, never a bare key, so the deep link `#<test>/heat-map/f=<file>&l=<n>&e=Ir` does not collapse to `#<test>/heat-map/e=Ir`. Plus `{theme:"title"}`, which is how a title set two levels down reaches the outermost badge. **outer→inner**: `"theme:reset-cols"` and `"theme:title?"`, the latter sent by `show()` when the frame already holds the wanted page (`href === page`, so no `location.replace` fires) to re-ask for a title that would otherwise go stale. A framed page's `setTitle` writes `""` into its own badge but still posts up and still sets `document.title`. Probe: `#<test>/heat-map` must leave `document.title` and the badge reading `<test> / heat map`, not `<test>`.
- Routing tests: jsdom (page loaded from an `http://localhost/` URL, `location.hash =` then a tick — `hashchange` is async) covers the heat map alone; the frame page needs Chrome (`location.replace` across documents isn't implemented in jsdom): copy `index.html` to `probe.html` beside it with an appended `<script>` that sets `location.hash`, awaits the mirrored canonical hash and writes a log `<pre>`, run with `--dump-dom --virtual-time-budget=30000`. Cross-origin `file://` frames are opaque — observe the outer hash/title/`history.length` only — **unless** `--allow-file-access-from-files` is passed, which makes `view.contentDocument` readable and lets one probe click through all three levels (overview → summary → heat map) and assert the *outer* hash after each step. That round trip is the regression test for URL-as-state: click a test, a view, a file, a line, then change the event, and the outer hash must end as `#<test>/heat-map/f=<file>&l=<n>&e=<ev>`; loading that same URL back must reproduce the identical outer/middle/inner hashes.
- Outer frame page (`body.frame`) never scrolls itself — only `main`/`iframe` children do (`overflow: hidden` on both `html:has(body.frame)` and `body.frame`, to avoid a real (non-overlay) scrollbar sub-pixel rounding gap that doesn't repro in headless Chrome).
- Heat map source table: columns `<event>`, `line`, `source`, `calls`, D1m, DLm, Bcm. No row-wide heat (`tr` carries only id/class/`data-ln`/title): the event, line and source cells each get the line's self heat inline, `calls` (cost of the calls made from the line, share of the event total) its own heat on the same scale, D1m/DLm/Bcm theirs (`extraCells`) — so no cell's text is ever contrast-colored against another cell's background. `EVS`/`EXTRA` (`callgrind_to_heatmap.py`) list every event the profile can produce (raw `events:` membership, derived only gated by `resolved_derived_events()` having all its terms) — **not** filtered by whether its total/magnitude happens to be zero, so the event dropdown and the D1m/DLm/Bcm columns stay layout-stable across profiles/diffs instead of columns appearing/disappearing based on what happened to change; a genuinely all-zero column just renders blank cells (`extraCells`'s `self ? fmtP(...) : ""`), no heat, no `NaN`. `TOTAL`/`MAXPX[key].total` guard `|| 1` for a zero-total event so percentages come out `0`, not `NaN`. Clickable-row hover cue = underline on `td.ln` (an inline heat `color` beats any stylesheet color, so a `--link` recolor can't show on heated lines). Minimap clone rows take their heat from the cloned `td.code` itself.
- Call counts are a metric of their own, heat-colored by share of every call the profile recorded (each call site's count, summed), log-scaled to the most-called function, same ramp/alpha as cost, event-independent: heat map `numCalls()` (`CALLS_TOTAL`/`CALLS_MAXP`; home functions `calls`, popup `call count` columns), summary `BuildReport.functions_table()` (`calls_total`/`calls_max_pct`). Speedscope untouched. Reader-facing rule: README.md "Colors".
- Heat map code view layout (`renderFile()`): `.fhead` band, `.chips` and the listing's `.tbl-cols` sit inside one `.srcwrap` (`width: max-content; min-width: 100%`) so the wrapper is exactly the sideways scroll range and the sticky band's background reaches its far right edge after the listing is dragged wider than the pane. Bands/chips get `contain: inline-size` (without it their *unwrapped* single-line width is what max-content takes, pushing the wrapper past the pane on every file). `td.code` clips (no `overflow: visible`) so nothing spills past the table. The listing has no side margins: its pane has no padding, so the symmetric-inset fill resolves to 0 on both sides and it runs edge to edge (source = the `grow` column) and dragging a column grows it rightward past the pane; it is a `bare` `table()` (no `.tbl` box) because `alignSticky` only stacks header cells outside a `.tbl` box under the sticky bands. Order gotcha: `minimapBuild()` runs **before** `Theme.init()` — the band narrows the pane by 110px and the fill measures the pane as it is at that moment. `centerRow()` (vertical only, centered in the part of the pane below `coverH()`) replaces `scrollIntoView`, which also pulled the pane sideways for a row wider than it.
- Heat map minimap (`#minimap`/`#mmBox`/`#mmViewport`): never scrolls itself and `#minimap` is never resized; `minimapLayout()`'s scale = `min(1, bandW/(MM_MIN_COLS·mmChPx), bandH/mmCloneH)` — pinned to `MM_MIN_COLS` (80) only, never widened to the file's longest line; the clone `table.src` has `width: 100%` + `table-layout: fixed` (fixed layout needs a non-auto table width, else the lone column sizes to the longest line and heat rows stop there) + `td { overflow: visible }`, so heat spans the band and longer lines are clipped by `#minimap`. `mmCloneH` = clone `offsetHeight`, read only after the band's `empty` class is removed (display:none measures 0). `mmViewport`'s fill is `rgba(245,246,250,0.36)`, border alpha `0.55`. Scroll sync caches nothing: `mmGeom()` reads live rects every time — `rows` = tbody height minus an open `tr.detail`, `above(y)` = row px above client-y `y` (popup excluded), `cover` = `coverH()` = `.band` heights + first `th` height, `head` = first `th` bottom. Only the `th` cells are sticky, the `<thead>` scrolls away — never measure the thead. Box top/height = `mmCloneH·mmScale` × fractions `above(head)/rows`, `(above(bottom)−above(head))/rows`; `mmScrollTo(r0)` is the inverse (click centers the clicked row on screen, drag moves the box). `minimapSync()` is also called after a popup opens/closes (`detailSet()`; changes visible rows without a scroll event). Verify with a DOM probe: rows with rect between first-th bottom and pane bottom must match `top/height` of `#mmViewport` mapped back to row numbers.
- Heat map detail popup (`.dbox`, `detailOpen()`): "copy" writes a plain-text twin built in parallel with the HTML (`tableText()` mirrors `table()` off the same `cols`/`rows`), not scraped `textContent` — a space-padded GFM pipe table so the columns line up pasted raw or rendered. Stashed as `tr.detail._copyText`; JS source embedded in a Python triple-quoted string needs literal `\n` written as `\\n` or it breaks the generated page's `<script>` (`node --check` the extracted script after touching this function). Line headline has two exact forms picked by whether the line is a function's entry line (`evLong()` gives the long event name): entry line → `path:ln self P% by <long event name>, H <EVENT_KEY>.` (no `in fnName`/`line`/`:` — the "entered here" heading right below already names it); otherwise → `path:ln in fnName: line self P% <long event name>, H <EVENT_KEY>` (no trailing period). Both forms append inline EXTRA (D1m/DLm/Bcm) stats whenever nonzero, so all per-line stats are handed over in one place rather than only as bare source-table columns. Function-entry heading reads `fnName by call count: self P%, total P%.` (dropped the old "is entered here — ... Called from (by call count):" phrasing since the table's own `call count` column already says that); without a call graph (`HAS_CALLS` false: a diff) it reads `fnName: self P%.` and no caller table or "(no recorded caller ...)" note follows.

## Current state (update this section as findings change)

No `lib/` change has come out of the profiling yet. Per-test numbers live in the reports (overview: native time, cycles, instructions per test), not here.

**Measurement facts (2026-09-19).**
- Callgrind cannot give per-call stacks or per-call time: `calls=` lines are aggregated (caller, callee) totals, nothing in the format records one call, an order, or a time; `--read-inline-info=yes` changes nothing observable; `--separate-callers=N` splits functions per caller chain — exact, still aggregated, no order (never feed such a file to the summary/heat map: functions come out named by full chain).
- Whole-build `-finstrument-functions` + `dev/cyg.c`: one top-level library call is 2 to 184 events depending on the test; 0 enter/exit mismatches in all 8 tests. Perturbation, native → traced build, one run: 152 → 154 ns/call at 2 events/call, 304 → 746 ns/call at 184 (an earlier session read 82 → 91 and 161 → 421: the box's native speed itself moves ~1.9× with host state, so only compare numbers from one run) — the hooks' cost sits inside every traced duration, so the flame graph is for shape and outliers, the perf log for speed.
- `rdtsc` on this box steps by 20 ticks = 10.02 ns (gcd of every consecutive stamp delta in a 16,384-record trace), so every flame-graph duration is a multiple of ~10 ns and the shortest enter→exit is one step. The recorder's hook going from 28 to 11 instructions is verified in the disassembly only: A/B over 10 pinned runs each reads 10.02 ns median per event for both at 184 events/call, and identical runs of one binary flip between 10/20/30 ns medians — the saving is below the clock's step.
- speedscope's evented format (`{type:"evented", unit:"nanoseconds", events:[{type:"O"|"C", frame, at}]}`) costs ~38 B per event as JSON: 10 KB ≈ 250 events.
- TSC: `constant_tsc nonstop_tsc rdtscp tsc_reliable`; measured 1.9962 tsc/ns.
- `perf stat -e cycles:u,instructions:u` works in this WSL2 (kernel 6.18 exposes the CPU PMU). `perf record` works too but samples.
- uftrace is not installed (apt candidate 0.18.1, needs sudo). A `dpkg -x` copy run with `--libmcount-path` hung in `uftrace record` (stuck at its `.channel` handshake, nothing recorded) — untested beyond that. It would replace `cyg.c` + the binary reader (own recorder, symbolizer, `dump --chrome`), add libc calls, threads and scheduler events, at a higher per-call cost than the rdtsc hook.

## Workflow

1. Baseline: `./build/tests/perf/perf <test>` a few runs (median of 3-5) for a quick read, but **real numbers only from the pinned RelWithDebInfo build**.
2. Profile via `dev/perf2html.sh` (or manual callgrind/gdb) on the RelWithDebInfo tree only.
3. Make one focused change.
4. Rebuild (`cmake --build build --target perf`, plus the lib if `lib/` changed) and re-run.
5. Compare: `dev/perf2html.sh --report=perf2html_modified_report` then `dev/perf2html_diff.sh`; keep only changes that measurably help AND leave everything else the test prints (counts, error totals) unchanged.
6. Record before/after numbers here (in "Current state") as you go.
7. Before calling anything final: full test suite (`tests/runtests.pl` or `ctest` from `build/` with `-DBUILD_TESTING=ON`) — this perf test alone doesn't validate correctness.
